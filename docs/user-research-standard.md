# 用户使用调研：方法与记录标准

整理日期：2026-10-27。  
定位：**标准文档**——规定怎么调研、怎么记结果。结果清单见 `docs/user-research-results.md`。

---

## 1. 调研目标

对齐产品主张「可验证 → 可信任」，不是堆「AI 很聪明」的观感分。

优先验证：

1. 用户能否在合理时间内找到目标公司与正确报告期。
2. 看到数字/结论后，能否**点回 PDF 原文**完成核对。
3. 题外问题时，系统是否乱编；软提示是否可接受。
4. 冷启动（池外公司）路径是否可理解（加入监控池 → 采集 → 再问）。

**非目标**：满意度星级刷高、未受控的「准确率问卷」、替客户虚构 POC 结论。

---

## 2. 对象与场景

参考 `docs/competition-submission-reference.md` 附录场景，收敛为三类 persona（可一人分饰）：

| Persona | 典型任务 |
|---|---|
| 业务分析 | 短时间搞清某公司最新经营表现，并核对关键数来源 |
| 研究 / 管理 | 同一公司多期营收、利润、ROE 对比 |
| 核验型读者 | 读完 AI 概览或问答后，必须回到原文页确认依据 |

创新大赛阶段：**暂无外部 POC 客户**；正式访谈未齐时，允许「内部走查 / 产品迭代观察」，但必须在结果表标注来源（见结果文档）。

---

## 3. 方法

推荐组合（单次 25–40 分钟）：

| 方法 | 用法 |
|---|---|
| 半结构访谈 | 开场 5 分钟：平时怎么读财报、最怕什么错 |
| 任务走查 | 给定 3–4 个任务，观察卡点，少打断 |
| Think-aloud | 请被试边做边说「我在找什么 / 我信不信这个数」 |

### 推荐任务清单（可裁剪）

1. 搜索公司（简称或全称）并打开最新正式报告。
2. 在概览找到一项核心指标，**点击角标**跳到 PDF 并确认高亮/页码。
3. 在追问栏问一个证据题（如「本期营收为什么变化」），点击答案出处。
4. （可选）问边界题（如短期股价），观察是否软提示而非胡编。
5. （可选）池外公司：加入监控池 → 立即抓取 → 理解等待态。

环境：尽量用与答辩一致的样本与文案；记录产品版本 / 日期 / 环境（本地或线上）。

---

## 4. 记录模板（字段标准）

每条会话或每条发现一行（写入 `docs/user-research-results.md` 表格）：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 如 `UR-2026-001` |
| `date` | 是 | Asia/Shanghai 日期 |
| `persona` | 是 | 上表三类之一，或「内部产品」 |
| `source` | 是 | `正式访谈` / `内部走查` / `产品迭代观察` |
| `task` | 是 | 对应推荐任务编号或简述 |
| `observed_friction` | 是 | 客观卡点（点不到、期次错、等太久等） |
| `quote` | 否 | 原话摘要，去标识 |
| `severity` | 是 | `S0` 建议 / `S1` 摩擦 / `S2` 阻断信任 / `S3` 数据错误风险 |
| `product_implication` | 是 | 对功能的具体含义（一句话） |
| `session_result` | 是 | `通过` / `部分通过` / `未通过`（相对成功标准） |

禁止：把内部走查写成「某券商客户访谈」；禁止记录手机号、工号、可识别姓名（可用「分析师 A」）。

---

## 5. 单次会话成功标准

同时满足才算「通过」：

1. 独立完成「打开正确公司 + 期次」或在提示后 1 次内纠正。
2. 至少一次**自主**完成角标或答案页码点回，并口头确认「能对上」。
3. 未出现被试把题外胡编当成可信投资建议且系统无边界提示的情况（若测了边界题）。

「部分通过」：主路径走通但有 S1 级摩擦（文案不懂、多点一次等）。  
「未通过」：无法完成点回，或期次/公司错到被试未察觉。

---

## 6. 隐私

- 结果文档只保留去标识摘要与严重级别。
- 原始录音/屏幕录像不入库；若需存放，放团队私有盘并在结果行注明「有原始介质、未公开」。
- 不在公开答辩材料粘贴可识别 PII。

---

## 7. POC 声明

**创新大赛产品阶段：暂无外部 POC（无试点客户合同、无驻场验收报告）。**  
答辩「验证效果」第三栏应写清「POC：暂无」；用单元测试 + 黄金题库结构 + 内部/访谈走查结论代替，不以虚构客户冒充。
