# 关键关系（已上线 v1）

> 组名：**关键关系**（与「关键比率」成对；勿用「值得看」「数字关系」作组名）。  
> 位置：四项核心指标下方、指标趋势上方。  
> 心智：**程序发现关系，模型辅助解释**——不是另一张指标卡，也不是又一段 AI 总结。
> 本页记录三类 v1 实现；“已上线”指仓库已接入业务界面，不代替线上部署验证。
> 扩展至 80 类的待实现规范见[财务关系分析标准](财务关系分析标准.md)，候选与程序/AI 分工见[80 类关系目录](财务关系目录.md)。

四项核心指标回答「数字是多少」，财报速览回答「整体怎么看」。关键关系补中间一层：

> **哪些数字需要放在一起看，它们说明了什么，又不能说明什么？**

---

## 1. 原则

| 层 | 谁做 | 产出 |
|---|---|---|
| 硬事实 / 口令 | 本地规则 | 数字、同比、页码、翻页缩放 |
| 关系是否成立 | 程序核对口径并计算 | 1～3 张卡：事实 + 怎么看 + 原因边界 |
| 关系「为什么」 | AI（用户点「追问原因」） | 进入现有检索问答，要求引用原文；双出处完整覆盖与语义支持仍需核验 |

一句话：**把速览的一句判断，展开成用户能看懂、能核验的推导过程。**

与既有口令原则一致：确定的走规则，不确定的解读走 AI。

---

## 2. 为何不全量复活「重点关注」

- UI 已下线：假阳性直接伤信任。
- 旧模块维数多，阈值一松就刷屏。
- **v1 做法**：不批发重开；目前接入 **3 类硬关系**，可展示同步改善（理解向），不只警报。三类不是后续检查范围的上限；扩展按独立目录与标准实施。

`lib/focus-highlights.ts` 可作阈值/素材，不是产品 UI 合同。

---

## 3. 卡片形态（每条）

1. **关系标题**（如「收入增长没有转化为利润增长」「盈利与经营现金流走势分化」）  
2. **事实行**：尽量含**两期数字**；需要时给出推导比率  
   - 归母净利率 = 归母净利润 / 营收（**不是毛利率**）  
   - 净现比 = 经营现金流 / 归母净利润（优先展示跨期变化）  
3. **怎么看：** 一句算术关系解读  
4. **原因：** 边界声明——无原文不写成本/造假等因果；v1 默认「原因待核验」  
5. **查看依据**（跳转出处）· **追问原因**（`draftAsk`，带双出处）

展示上限：**3** 张。

### 空态（整块仍显示）

| 状态 | 文案 |
|---|---|
| 已检查、无明显背离/值得列出的同步 | **已检查的关系未发现明显背离**（禁止「暂无风险」） |
| 三类均缺可比数据 | **缺少可比数据，暂无法判断** |

## 4. v1 三类关系

| 关系 | 帮用户理解的问题 | 何时出卡 |
|---|---|---|
| 营收 × 归母净利润 | 收入增长有没有转化为利润？ | 同比符号背离；或两边同比均 ≥5% 的同步增长 |
| 归母净利润 × 经营现金流 | 盈利与现金流是否匹配、走势是否分化？ | 优先跨期：水平分化 / 净现比恶化 / 利润+且 OCF−；也可展示同步改善。无上期时退回本期净现比阈值 |
| 归母净利润 × 扣非净利润 | 盈利中有多少来自非经常性损益？ | 非经常性占比 ≥20%，或扣非后为负；缺字段则跳过该类型 |

实现：`lib/metric-relationships.ts`（阈值复用 `FOCUS_THRESHOLDS`）。

## 5. v1 非目标

- 行业故事 / Peer 故事线  
- 投资建议 / 买卖点  
- 大而全十维排雷（旧重点关注批发复活）  
- 自动把 MD&A 写进「原因」（v1 stub 为待核验；追问时由聊天拉证据）  
- 无出处的「可能存在风险」空话  

---

## 6. 决赛 PPT / 答辩

**金句（半行）：**

> 找得到是底座；看得懂关系是 AI 主场——程序发现关系，模型辅助解释。

挂在「证据 / 确定的靠规则」一带即可，不必单开专题页。演示：点「查看依据」跳页 → 点「追问原因」看 AI 双出处解释。
