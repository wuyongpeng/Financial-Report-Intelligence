# 用户调研

整理日期：2026-10-28。  
合并原「用户调研标准」与「用户调研结果」：先定方法，再列已记录发现。

## 1. 目标

对齐主张「可验证 → 可信任」，不是刷「AI 很聪明」的观感分。

优先验证：

1. 能否较快找到目标公司与正确报告期  
2. 看到数字/结论后，能否**点回 PDF**完成核对  
3. 题外话是否乱编；软提示是否可接受  
4. 池外冷启动（加入监控池 → 采集 → 再问）是否可理解  

**非目标：**未受控的准确率问卷、虚构 POC 客户结论。

## 2. 对象与方法

| Persona | 典型任务 |
|---|---|
| 业务分析 | 短时间搞清最新经营表现，并核对关键数来源 |
| 研究 / 管理 | 同一公司多期营收、利润、ROE |
| 核验型读者 | 读完概览或问答后必须回原文确认 |

推荐单次 25–40 分钟：半结构访谈 + 任务走查 + Think-aloud。

推荐任务：打开最新正式报告 → 点指标角标回 PDF → 追问证据题并点出处 →（可选）边界题 / 池外冷启动。

## 3. 记录字段

每条发现一行：`id` · `date` · `persona` · `source`（正式访谈 / 内部走查 / 产品迭代观察）· `task` · `observed_friction` · `quote`（可选）· `severity`（S0–S3）· `product_implication` · `session_result`（通过 / 部分通过 / 未通过）。

禁止把内部走查写成「某券商客户访谈」；结果只保留去标识摘要。

单次「通过」须同时：打开正确公司+期次（或一次纠正）；至少一次自主点回并确认对得上；边界题未把胡编当投资建议且系统无提示。

## 4. POC 声明

**创新大赛阶段：暂无外部 POC**（无试点合同、无驻场验收报告）。验证效果用单测 + 黄金题库结构 + 内部/访谈走查代替，不以虚构客户冒充。

## 6. 可上材料的一句结论

用户要的不是「自动摘要」，而是：**报告期不错、结论能点回原文、系统知道边界**。  
上表来自产品迭代观察 / 内部走查，用于排优先级，**不是**外部客户满意度统计。
