# 技术架构

Eva 如何把公开财报变成可核对的阅读台：采集与解析、三栏阅读、智能追问，以及运营后台。

## 1. 总体数据流

```text
交易所 / 巨潮公告列表
  → Worker 发现、去重、限速下载官方 PDF
  → 逐页文本提取
  → 规则抽取核心指标（字段名、页码、置信度）
  → PostgreSQL（公告、指标、页文本、运行与复核）
  → Web 阅读台（三栏详情、图表、问答）+ 可选财报速览
```

采集温和：明确 UA/Referer、限速与重试；只取公开披露，不绕过访问控制。

## 2. 逻辑分层

```text
数据源（交易所 / 巨潮）
  → 采集 Worker（发现 · 下载 · 解析 · 可选速览）
    → 存储（PostgreSQL + 本地 PDF）
      → Next.js 接口（阅读 / 分析 / 问答 / 运维）
        → 智能层（意图 · 检索 · 引用校验 · 模型闸门）
          → 展现（首页 · 三栏详情 · 角标回原文 · /sources · /admin · /docs）
```

常见部署：Docker Compose 上的 `app`、`worker`、`db`、`caddy`；PDF 与库目录持久化。

## 3. 解析与可核对

- **规则优先**：营收、归母净利、EPS、ROE 用确定性字段与单位换算；有调整前/后时同比取调整后。
- **可追溯**：保留来源字段、页码、置信度与人工复核标记。
- **异常不上线**：抽不全则「部分解析」，不填猜测数。
- **指标联动**：程序核对硬关系，界面最多 3 条；关系任务失败不拖垮基础解析。
- **角标回原文**：概览与问答中的页码可跳左栏 PDF 并高亮。

## 4. 问答与检索

详情页右侧追问走流式接口。流水线概要：

```text
问题规划 → 检索当期页文本与结构化指标 → 作答策略 → 模型生成 + 引用校验
```

有结构化数据则优先直答；证据不足明示；越界短答并提示边界。引用校验失败则降级，不为凑出处乱挂页码。不访问未入库外部数据，不做投资建议。


## 5. 阅读台

| 面 | 说明 |
|---|---|
| 首页 | 按代码 / 简称 / 全称检索，进详情 |
| 详情 | `/[六位代码]` 左原文 · 中概览 · 右追问；期次可切换 |
| 数据采集 | `/sources` 看发现 → 下载 → 解析进度 |
| 文档 | `/docs` 手动进入；对外四篇产品文档 |

## 6. 运营后台（`/admin`）

需管理员密码。五个子模块：

| 模块 | 做什么 |
|---|---|
| **解析总览** | 看各公司期次解析状态与同比；单行或批量 **重解析**、**审核通过**、**标记异常** |
| **指标核对** | 对照抽取结果与披露口径，快速筛异常行 |
| **访问审计** | 访问 / 提问 / 反馈日志；可 AI 归纳主题 |
| **用户调研** | 问卷回收与汇总；可 AI 归纳 |
| **反馈收集** | 站内与回答反馈列表；可 AI 归纳 |

运营动作与阅读台分离：主路径保持轻，质控与复盘走后台。
