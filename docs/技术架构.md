# 技术架构

整理日期：2026-10-28。  
说明 Eva 的数据流、服务分层、解析质控与问答检索。部署形态为单 VM 模块化单体。

## 1. 总体数据流

```text
SSE / SZSE / BSE / CNINFO 公告列表
  → Worker 增量轮询、公告 ID 去重、源站健康记录
  → 下载官方 PDF 至本地归档
  → PDF 逐页文本提取
  → 规则提取四项核心指标（保留字段名与页码）
  → PostgreSQL（公告、指标、页文本、运行与复核）
  → Next.js Web（三栏阅读、图表、问答）+ 可选智析速览
```

温和采集：明确 UA/Referer、限速与重试；不绕过验证码或访问控制。

## 2. 逻辑架构（示意）

```text
数据源层（交易所 / 巨潮）
  → 采集层 Worker（发现 · 去重 · 下载 · 解析 · 可选速览）
    → 存储层（PostgreSQL + 本地 PDF + 运行时状态）
      → 服务层 Next.js Route Handlers（阅读 / 分析 / 问答 SSE / 运维）
        → 智能层（意图 · 检索 · 提示 · LLM 闸门 · 引用校验）
          → 展现层（首页 · 三栏详情 · PDF 证据 · /sources）
```

Docker Compose 常见服务：`app`、`worker`、`db`、`caddy`。PDF 与数据库目录持久化；迁企业 PG/对象存储时替换适配层即可。

## 3. 服务端分层

HTTP 入口在 `app/api`。依赖方向：

```text
Route Handler（HTTP / 鉴权 / 序列化）
  → Application Service（用例编排）
    → Repository Interface（领域端口）
      → PostgreSQL Adapter（SQL 与行映射）
```

样板：`modules/reports/`（list-reports → report-repository → postgres 适配）。`contracts` 只承载 HTTP 请求/响应协议，不写 SQL。

## 4. 解析与质量控制

- **规则优先**：营收、归母净利润、EPS、ROE 用确定性字段定位与单位换算。  
- **可追溯**：`source_label`、`source_page`、`confidence`、`verified`。  
- **人工复核**：核对 PDF 后标记已复核并记事件。  
- **异常不上线**：抽不全则「部分解析」，不填猜测数。  
- **关系分析**：约 10 类在应用层程序计算，界面最多 3 条（关注度排序 + 主题去重）；扩展不得拖垮基础解析事务（见[财报分析说明](财报分析说明.md)）。

## 5. 问答与检索

入口：`app/api/chat`（SSE/JSON）。内部流水线：

```text
QuestionPlanner → QueryPlan
  → RetrievalRepository → PassageRetriever（当前关键词规则）
  → Retrieval Orchestrator → Answer Policy
  → LLM Answer Generator + Citation Validator
```

当前**不宣称**已实现向量 RAG；后续可在 `PassageRetriever` 后加全文/向量/混合，而不改 Chat API。`lib/rag.ts` 作兼容组装入口。

策略要点：结构化直答、证据不足明示、越界软拒；引用校验失败则降级，不为凑出处乱挂页码。问答不访问未入库外部数据，不提供投资建议。

## 6. 关键界面与运维面

| 面 | 路径 / 说明 |
|---|---|
| 首页 | 搜索、卡片、语音入口 |
| 详情 | `/[六位代码]` 三栏；兼容 `/?code=` |
| 数据采集 | `/sources`（旧 `/crawl` 重定向） |
| 文档中心 | `/docs` 手动进入；只列对外五篇 |
| 审计 | `/admin/audit`（需管理员密码） |
