# 功能评测

整理日期：2026-10-28。  
说明 Eva **怎么验、验了什么、绝不能怎么写**。验证效果靠可复现的测试与走查，不靠空准确率百分比。

## 1. 验证拼图

| 证据 | 作用 | 诚实边界 |
|---|---|---|
| 单元测试 | 护解析、队列、契约、意图等纯逻辑 | 不证明任意真实财报「整体准确率」 |
| 黄金题库 | 固定验收题骨架（结构 / 证据 / 同行 / 边界） | `manualScore` 未填完前**禁止**报准确率 % |
| 人工走查 / 演示点回 | 证明角标与答案能回到 PDF | 不等于客户 POC |
| 用户调研 | 场景摩擦与信任结论 | 见[用户调研](用户调研.md)；暂无外部 POC |

## 3. 黄金题库

| 项 | 值 |
|---|---|
| 文件 | `data/golden-questions.json` |
| 脚本 | `npm run eval:questions`（`scripts/eval-questions.ts`） |
| 题目数 | **24** |
| `manualScore` 非空 | **0**（截至 2026-10-28） |

按 `kind`：structured 4 · evidence 18 · peer 1 · boundary 1。

脚本**只检查**题目是否具备可评分字段，打印 OK/MISSING；**不**调用 LLM、不比对答案、不计算准确率。因此「24/24 字段齐全」≠ 模型答对。

### 禁写

- 在 `manualScore` 仍全空时声称「黄金题准确率 xx%」  
- 把字段校验通过写成「自动评测已通过（模型）」  
- 虚构客户验收分  

可写：题库结构、人工评分进度（当前 0/24）、现场演示「点回原文」。

## 4. 建议的人工评分约定

1. 固定样本公司 + 期次。  
2. 用产品追问栏真实作答，记录能否点回。  
3. 对照每题 `rubric` 打分并回写 `manualScore`。  
4. 对外只写「已人工评 x/24」；未评完写「结构已备、人工评分进行中」。

## 5. 功能走查清单（决赛可用）

不必写成空分数，按项勾选即可：

- [ ] 搜索公司 → 打开正确报告期  
- [ ] 四项指标角标跳 PDF 并高亮  
- [ ] 指标联动展开见数据角标与提示  
- [ ] 追问证据题 → 答案页码可点回  
- [ ] 边界题（如短期股价）→ 软提示而非胡编目标价  
- [ ] （可选）池外公司：加入监控池 / 立即抓取，等待态可理解  

更细的操作剧本与历史测试计划见 `docs/_archive/`（决赛演示脚本、参赛测试计划、测试执行手册等）。
