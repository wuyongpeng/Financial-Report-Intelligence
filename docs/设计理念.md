# 设计理念

Eva 的产品与实现取舍，可以收成六个字：**极简 · 易懂 · 可核对**。

一句话串起来：**极简决定看什么，易懂决定怎么看，可核对决定敢不敢信。**

本文讲「为什么这样设计」；「现状怎么做」见 [技术架构](技术架构.md)，能力清单见 [产品介绍](产品介绍.md)。

## 产品设计：极简 · 易懂 · 可核对

面向会读披露、但不想被几百页 PDF 淹没的读者。主路径尽量像 C 端产品：少步骤、少入口、动作自解释；信任来自能回原文，而不是「AI 说得很自信」。

| 理念 | 做法 | 用户得到什么 |
|---|---|---|
| **极简** | 主路径只有两页：首页检索入口 + 详情一体化三栏。概览先给财报速览与四项核心指标，复杂模块折叠或后置；管理、采集、文档不进主舞台 | 先看到最该看的，不被旁路入口打断 |
| **易懂** | 左栏原文（事实）、中栏概览（结论）、右栏追问，对应「先看披露 → 再看结构化判断 → 再深挖」的自然顺序；数据和判断分区呈现 | 分得清哪些是披露事实、哪些是归纳；核对时视线平移即可 |
| **可核对** | 指标与结论旁带溯源角标；一点，左栏 PDF 跳页并高亮对应原文 | 不必先相信 AI，可以验证 AI |

### 极简

财报动辄上百页，用户缺的往往不是信息，而是取舍。Eva 故意收窄主路径：

- **两页叙事**：进站搜公司，进详情三栏阅读；其余（`/docs`、`/sources`、`/admin`）是运维或答辩入口，不抢戏。
- **概览先抓重点**：财报速览给态势标签与一两句总结；下方固定四项核心指标（营收、归母净利、EPS、ROE），再展开指标联动、趋势与深度归因。
- **不做的也写清楚**：不做荐股、目标价、「能不能买」；状态如实展示，不拿模拟数填空。

### 易懂

界面结构对齐读财报的思路，而不是对齐后台模块名：

- **事实**：左栏 PDF / 提纲 / 搜原文，保留披露原貌。
- **结论**：中栏把已解析数字与程序核对关系摊开，降低「从原文里自己找数」的门槛。
- **追问**：右栏围绕同一份报告继续问；答案带页码，题外话短答并提示边界。

降低理解门槛，不等于替用户下投资结论；复杂留给追问，而不是一上来堆满表。

### 可核对

信任来自动作，而不是口号：

- 每个关键结论尽量带 **[Pxx]** 一类角标；点击后左侧原文自动定位并高亮。
- 用户不需要先相信模型，而是可以当场对照披露。
- 「可核对」也约束产品边界：答不出、缺数据、超出当期报告时，宁可说清边界，也不编造出处。

## 技术实现上的设计理念

产品六字落到工程上，对应三条取舍（细节见技术架构）：

1. **确定的走规则，不确定的解读走 AI**  
   核心指标抽取、单位换算、指标联动硬关系，优先程序与规则；模型负责在给定证据里写短解释，不替代数值计算。

2. **证据先行，答案可回原文**  
   检索与页码在解释之前就要能落到 PDF；没有支撑就不把猜测写成「已核验事实」。

3. **主路径与旁路分离**  
   阅读台保持轻；采集、复核、管理能力另入口存在，避免把 C 端阅读做成后台工作台。
