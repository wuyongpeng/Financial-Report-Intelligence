## 二、业务痛点及需求拆解

### 2.1 业务背景

上市公司定期披露的财报包含经营成果、盈利能力、资产质量及管理层讨论等重要信息，是业务分析、公司研究和经营跟踪的重要依据。但单份财报篇幅长、表格多、口径复杂，使用者通常需要在公告网站、PDF 阅读器和表格工具之间反复切换，才能完成基础的数据查找、历史比较和原文核验。

在实际使用中，用户不仅希望快速获得营业收入、归母净利润、每股收益、净资产收益率等核心指标，更需要确认数据来自哪一份公告、哪一页、哪个原始字段。传统人工阅读效率较低，通用问答工具又难以保证数据来源明确、报告期不混淆。因此，需要建设一套以官方公开财报为基础，兼顾自动化提取、可视化分析和原文可追溯能力的轻量化分析工具。

### 2.2 核心业务痛点（列出 2—3 个最关键痛点）

1. **财报阅读成本高，关键数据定位效率低。**
   财报通常包含数十至数百页内容，用户需要手动检索并识别不同口径的财务字段；同一指标还可能因单位、合并范围和报告期不同而产生理解偏差。

2. **数据结论缺乏可核验链路。**
   现有信息整理方式常只保留结果，不保留对应公告、页码和原始字段。用户发现异常后需要重新翻阅 PDF，无法快速判断数据是否可靠、是否经过复核。

3. **跨期和同业比较过程繁琐，容易发生口径混用。**
   人工整理多期数据成本高，季度、半年和年度数据可能被混合比较；同业比较还受限于数据覆盖度和口径一致性，容易形成误导性结论。

### 2.3 本项目解决范围与边界

#### 1. 本项目重点解决

- 聚合交易所等官方公开渠道披露的上市公司财报，建立持续增量更新的财报数据基础。
- 从财报 PDF 中提取营业收入、归母净利润、基本每股收益（EPS）和净资产收益率（ROE）四项核心指标，并保留字段名、来源页码和置信信息。
- 提供公司搜索、财报详情、多期趋势、同报告期同业比较、PDF 原文阅读与证据定位能力。
- 提供基于已入库财报内容的问答辅助能力，使回答可关联结构化指标和原文页码。
- 通过“已上线、待复核、部分解析、待处理”等状态向用户透明展示数据质量和处理进度。

#### 2. 本项目明确不解决（边界约束）

- 不提供股票买卖、估值目标价、涨跌预测等投资建议。
- 不将缺失数据、未解析数据或低置信数据补造为完整结论；数据不足时明确展示空态或限制说明。
- 不替代专业审计、投研尽调和人工复核流程；已上线数据仍以管理员复核和官方原文为准。
- 不采集非公开数据，不绕过验证码、访问控制或数据源限制；仅处理公开披露信息并采用低频增量采集。
- 当前 MVP 不覆盖全量财务科目、复杂分部数据、费用明细归因及完整信用评级。

### 2.5 预期效果（量化指标）

## 三、整体方案设计

### 3.1 设计思路

本项目采用“官方数据采集—结构化解析—证据保留—可视化分析—问答辅助—人工复核”的闭环设计。

首先，系统从交易所公开公告列表发现新增财报，并以公告 ID 和逻辑 ID 去重，避免重复下载和处理。随后将官方 PDF 下载归档，逐页提取文本与表格信息，通过规则优先的方式识别四项核心指标。在生成结构化指标时，系统同步保存原始字段名称、页码、置信度和复核状态，确保页面中每个结论都能回到官方原文。

面向用户侧，系统将“公司—报告期—指标—证据”组织为连贯的阅读路径：用户可先检索公司，再查看当前报告的核心指标、历史趋势和同业情况；当需要验证时，可直接跳转至对应原文页。问答模块仅基于已入库的结构化数据和 PDF 页文本生成回答，避免使用来源不明的外部信息。对解析不完整或尚未复核的数据，系统通过状态提示和空态表达边界，而非追求表面完整性。

### 3.2 技术选型与工具说明

| 技术/工具 | 用途与选择依据 |
| --- | --- |
| Next.js + TypeScript | 构建前后端一体化 Web 应用，兼顾页面交互、API 路由和类型安全，便于快速交付 MVP。 |
| PostgreSQL | 存储公告元数据、核心指标、PDF 页文本、任务状态和人工复核记录，适合结构化查询与数据一致性管理。 |
| Docker Compose | 将 Web 应用、采集 Worker、数据库和反向代理封装为单机可部署服务，降低演示和交付环境搭建成本。 |
| 独立 Worker | 按固定周期执行公告发现、下载、解析和失败重试，避免采集任务影响前台使用体验。 |
| PDF 文本/表格解析 + 规则提取 | 面向核心财务字段采用确定性规则和单位换算，优先保障数据可解释性和稳定性。 |
| OpenAI 兼容模型接口（可选） | 用于生成带证据的财报问答与概览；模型不可用时回退至结构化数据和原文证据，保证基础能力可用。 |
| Caddy | 提供反向代理与 HTTPS 能力，简化单机部署场景下的网络入口配置。 |

### 3.3 产品、交互或业务层面创新点

1. **“指标—页码—原文”一体化溯源交互。**
   不只展示数值，还将每项指标与原始字段、报告页码和 PDF 核验入口关联，降低用户验证成本。

2. **数据状态驱动的可信展示。**
   将机器解析、待复核、已上线和部分解析状态直接呈现给用户；对缺失指标不填零、不猜测，使数据可信度成为产品界面的一部分。

3. **结构化数据与非结构化原文协同问答。**
   问答不是仅依赖模型生成，而是结合核心指标、报告期、同业覆盖范围及相关 PDF 页文本，并以证据卡片辅助核验。

4. **严格控制比较口径。**
   多期趋势与同比比较遵循同报告期原则，Q1、Q3、半年报和年报不混算；同业比较仅在真实覆盖数据范围内进行，减少“伪精确”的分析结果。

5. **轻量化、可平移部署。**
   MVP 可在单台虚机完成运行，数据库与文件存储适配层相对独立，后续可平滑迁移至企业 PostgreSQL 与对象存储。

## 四、Demo 原型说明

### 4.1 Demo 可演示的核心功能

1. **公司搜索与报告进入：** 在首页输入公司简称或六位证券代码，进入公司详情页并选择已解析报告期。
2. **核心指标总览：** 查看营业收入、归母净利润、EPS、ROE 四项指标及其数据状态。
3. **原文证据核验：** 点击指标来源信息，查看原始字段、页码、提纲文本及 PDF 高亮位置。
4. **多期趋势分析：** 在核心指标多期趋势中切换指标，查看同类型报告期的历史变化。
5. **同行业比较：** 切换 ROE、营业收入或归母净利润，在已覆盖的同报告期公司范围内完成基础比较。
6. **财报问答：** 输入“管理层如何解释本期净利润变化”等问题，查看基于财报内容生成的回答及页码证据卡片。
7. **运营与质量管理：** 展示采集任务、数据源健康情况、报告处理状态和管理员复核能力。

### 4.2 Demo 尚未覆盖，但未来规划实现的能力

以下能力计划在 **10 月底终审前** 优先完成或增强：

1. **扩大报告与公司覆盖范围。** 完善监控池，提升重点行业和重点公司的报告期覆盖度，并持续补充官方数据快照。
2. **提升解析准确率与复核覆盖。** 增加不同财报版式的字段规则、异常检测和人工真值样本，提升四项核心指标的完整率、准确率和已复核比例。
3. **扩展财务分析维度。** 在数据质量满足要求后，逐步增加现金流、偿债、盈利质量、费用率和业务分部等指标；对于数据不足场景继续保留边界提示。
4. **优化问答评估与追问体验。** 建立标准问题集与答案评测机制，增强跨页证据整合、追问上下文管理和回答可靠性提示。
5. **完善运营能力。** 增加数据源异常告警、复核任务分配、解析失败归因统计和覆盖率看板，支持持续运营。
6. **增强展示体验。** 优化移动端阅读、PDF 高亮准确度、图表交互与分享导出能力，提升 Demo 展示完整性。

### 1. 用户 / 场景调研记录（参考写法）

**典型使用场景：**

- 业务分析人员需要在短时间内了解某家上市公司的最新经营表现，并核对关键数值来源。
- 研究或管理人员需要比较同一公司连续多个报告期的营收、利润和 ROE 变化。
- 用户在阅读 AI 概览或问答结论后，需要快速回到财报原文验证依据。

**调研结论：**

用户关注的并非单纯“自动生成摘要”，而是结果是否可信、能否快速核验、报告期是否正确。因此，产品优先投入官方来源、页码溯源、状态透明和同口径比较能力，而不是扩展未经验证的结论生成。
